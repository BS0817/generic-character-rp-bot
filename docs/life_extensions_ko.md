# 선택형 생활 확장과 기능 분류

이 문서는 다음 업데이트의 개발 소스를 설명합니다. 정식 Windows 배포본은 Releases에서 확인하세요. 기존 설정·토큰·프롬프트·기억은 교체하지 않습니다. 새 기능은 기본적으로 꺼져 있으며, 셋업에서 저장하고 봇을 재시작해야 적용됩니다.

## 기능 ON/OFF 목록

셋업 → **세계관 · 기능**에서 다음 묶음의 제목과 구분선 사이에 체크박스를 표시합니다. 기능을 묶은 것은 화면 표시만 바꾸며 저장 키와 의존성은 유지합니다.

| 묶음 | 설정 종류 |
|---|---|
| 대화 · 말투 · 공통 규칙 | 공통 프롬프트, 반복·관계 검사, 대화 방식, 자율발언, 봇 간 대화 |
| 기억 · 관계 · 대화 범위 | 기억, 관계, 개인 RP, DM, 오프라인 멘션 복구 |
| 월드 · 장소 · 이동 | 월드 시뮬레이션, 자동 이동, 좌석, 외출, 약속, 이벤트 |
| 수면 · 기상 · 복장 | 실제 수면, 수면 품질, 낮잠, 기상 호출, 주말 수면, 준비 루틴, 복장 취향·일정·상태 |
| 식사 · 조리 · 정리 | 식사 단계, 음식·식재료 재고, 설거지 |
| 활동 · 사용자 행동 · 물건 | 단계별 활동, 사용자 행동, 사물 상태, 공동 여가, 부탁·쪽지, 분실물, 대여 |
| 날짜 · 일정 · 기념일 | 달력, 계절 날씨, 요일 일정, 영업시간, 기념일 |
| 상태 표시 · 운영 | Discord 상태, 활동 표시, 관리자 속마음, 통계, 정기 AI 진단 |

필수 기능이 꺼져 있으면 함께 켤 항목을 안내합니다. 상위 기능을 끌 때는 함께 끌 항목을 안내하며 취소하면 원래 체크 상태로 돌아갑니다. 관리 화면 자체는 별도 기능 스위치 없이 사용할 수 있습니다.

## 음식 재고와 세트

장소 탭의 **음식 재고 정의**에 다음처럼 입력합니다. 기존 메뉴 목록은 상점의 일반 메뉴이며 사용자 준비 재고와 별도입니다.

```json
{
  "토스트": {
    "aliases": ["토스트 빵"],
    "unit": "인분",
    "hunger": 35,
    "expires_minutes": 180,
    "dishes": 1,
    "ingredients": {"빵": 1}
  },
  "차": {"unit": "잔", "hunger": 5, "dishes": 1}
}
```

`hunger`는 한 단위의 허기 회복량, `expires_minutes`는 준비 후 유효 시간, `dishes`는 섭취 후 생기는 식기 수입니다. 조리 재고 기능을 켜면 `ingredients`의 재료가 실제로 있을 때만 사용합니다. 일반 메뉴 식사도 섭취 단계에서 한 번만 허기를 줄입니다.

- 등록 장소에서 `토스트 두 인분을 준비했다`처럼 완료한 행동을 말하면 비멘션 메시지도 확인합니다. 질문·제안·계획·부정·인용·과거 보고는 반영하지 않습니다.
- `/음식준비 음식:토스트,차 수량:2`는 함께 준비한 두 세트를 만듭니다. 같은 명령의 구성품만 세트로 연결하며 다른 사람이 따로 준비한 음식을 합치지 않습니다. 미등록 음식은 기본값(인분, 허기 회복 35, 유효 180분, 식기 1)으로 명령 등록할 수 있습니다.
- 수령과 섭취는 별도입니다. 캐릭터가 받은 음식은 들고 이동할 수 있고 실제 식사 단계에서만 섭취합니다. 만료·부족한 재고는 섭취하지 않습니다. 야외는 날씨와 기온을 확인합니다.
- 자연어 해석이 애매하면 반영하지 않습니다. 정확한 구성품·수량은 음식준비 명령을 사용하세요.
- `/재료상자 종류:놓기 내용:빵:3,우유:2` → 상자 ID로 `발견` → `정리` 순서로 진행하면 재고에 추가됩니다. 같은 상자를 다시 정리하지 않습니다.
- 식재료 수량과 사용한 식기는 **생활 자료**에서 확인·보정합니다. 보정 전후 값은 변경 이력에 남습니다.
- `설거지 담당을 예약했다`는 30분 동안 담당을 예약합니다. 다른 사람의 설거지를 제한하며 시간이 지나면 해제합니다. `설거지 두 개를 했다`처럼 일부만 씻을 수도 있습니다.

확인 반응을 남기지 못해도 저장된 행동을 다시 적용하지 않습니다. 메시지 ID와 재고 변경을 같은 SQLite 트랜잭션으로 기록합니다.

## 사물 상태와 관리 필요

장소의 기존 **주변 사물**은 설명용 목록입니다. 변경할 사물은 **변화 가능한 사물·행동**에 따로 등록합니다.

```json
{
  "창문": {
    "properties": {"열림": false},
    "actions": {"열었다": {"열림": true}, "닫았다": {"열림": false}}
  },
  "화분": {
    "properties": {"수분": 100},
    "actions": {"물을 줬다": {"수분": 100}},
    "drift": {"수분": -2},
    "limits": {"수분": [0, 100]},
    "manage_below": {"수분": 30},
    "auto_manage": true,
    "manager": "",
    "manage_action": "물을 줬다"
  }
}
```

`drift`는 시간당 숫자 변화량입니다. 관리 기준 이하가 되면 캐릭터 문맥과 생활 자료에 필요 상태를 표시합니다. 지정 담당자가 다르거나 다른 일을 진행 중이면 보류 이유를 표시합니다. 제안만으로 상태를 바꾸지 않고 실제로 전송한 완료 행동을 확인합니다. `outdoor: true`이고 `젖음` 속성을 명시한 사물만 비·눈으로 젖게 됩니다. 실내 의자에 젖음을 자동 추가하지 않습니다. 오프라인 변화는 재시작 후 첫 확인에서 최대 10분까지만 적용합니다.

## 공동 여가

장소의 공동 여가 설정 예시입니다. 사용할 좌석은 먼저 좌석별 정원에 등록하세요.

```json
{"체스": {"capacity": 2, "minutes": 30, "seat": "테이블"}}
```

`체스에 참여한다` / `체스를 구경한다`처럼 실제 전송한 행동을 확인합니다. 기존 모임을 먼저 사용하며 정원이나 자리가 부족하면 구경으로 등록합니다. 공동 좌석은 정원 2명 이상이어야 합니다. 모집은 최대 5분, 두 참가자가 모이면 놀이를 시작합니다. 놀이 시간은 30~120분이며 모집 시간과 구분합니다. 이동·수면·종료 후 좌석을 다시 점검합니다. 참여자의 실제 현재 장소를 모임 장소와 대조합니다.

## 부탁·쪽지·물건

본서버의 등록 장소에서 `/생활행동`을 사용합니다.

- **부탁 / 쪽지:** 수신 캐릭터 키와 내용을 지정합니다. 24시간 유효합니다. 부탁은 제안·수락·진행·완료·거절·취소·만료를 구분합니다. 수신 캐릭터의 실제 공개 발언에 `#ID 수락한다` 같은 단계가 있을 때만 갱신합니다.
- **쪽지:** 해당 장소에 남습니다. 수신자가 그 장소에 도착해야 발견합니다. 비밀 내용은 수신자의 문맥만 참고하며 공개 운영 진단에 넣지 않습니다.
- **부탁취소:** 본인이 등록한 부탁 ID를 지정합니다.
- **물건놓기:** 사용자 소유 물건을 장소에 보관하고 ID를 받습니다.
- **분실신고 / 발견 / 반환 / 물건회수 / 대여:** 이름 칸에 기존 물건 ID를 입력합니다. 주인과 보관자를 구분하며 발견했다고 주인을 바꾸지 않습니다. 주인만 분실·대여를 지정하고 보관자만 반환합니다.

모든 장소·캐릭터·메뉴는 사용자 설정을 사용합니다. DDL RP의 세계관 이름·인물·메뉴·시간표를 고정하지 않습니다.

## 수면·루틴·복장

실제 수면 기능을 켜면 캐릭터의 **필요 수면 시간**과 **시간당 피로 회복량**을 사용합니다. 취침 시각을 저장하여 재시작 후 이어 계산합니다. 시작 기록이 없으면 잤다고 추측하여 회복하지 않습니다. 짧게 자도 피로를 일괄 초기화하지 않습니다. 수면 품질과 방해 기록은 별도로 반영합니다.

주말 추가 수면은 세계 달력의 토·일요일에 적용합니다. 이미 깨어 있는 캐릭터를 다시 재우지 않습니다. 기상 호출은 같은 장소에서 직접 요청한 06~12시의 `일어나`, `기상`, `깨워` 표현을 확인하고 실제 수면량·수락 성향에 따라 일어남·10분 미룸·거부·무응답을 선택합니다. 일어남은 ⏰, 나머지는 💤 반응을 남깁니다.

기상 준비는 정신 차리기·몸단장·아침 식사 준비로 이어집니다. 캐릭터의 몸단장 장소를 지정하면 출입 조건과 장소의 동시 이용 정원을 확인합니다. 정원 0은 제한 없음이며 대화 중에는 루틴 시간을 미룹니다. 기상 루틴 후 실제 식사는 식사 기능과 허기·메뉴 조건을 따릅니다.

수면 복장과 날씨별 낮 복장은 등록한 옷만 사용합니다.

```json
[{"outfit": "회색 코트", "weather": ["비", "눈"]}, {"outfit": "기본 셔츠", "weather": []}]
```

먼저 일치하는 날씨 복장, 없으면 날씨 목록이 빈 기본 낮 복장, 마지막으로 기존 현재·기본 복장을 사용합니다. 복장 취향을 새 옷의 소유 사실로 바꾸지 않습니다. 월드 복장은 개인 RP·DM의 독립 장면에 강제로 전달하지 않습니다.

## 모니터링·통계·운영

- **생활 자료:** 음식·수령 음식·재료·식기·사물·여가·부탁·쪽지·물건·상자·관리자 속마음과 변경 내역을 확인합니다. 설정 편집과 실제 운영 자료 수정은 별도입니다. 오류·불확정 작업은 Discord 기록을 확인하고 완료/중단으로 정리할 수 있으며 자동 재전송하지 않습니다.
- **생활 통계:** 최근 1·6·24시간, 캐릭터·장소 필터, 평균 허기·피로 그래프, 수면·낮잠·외출·연결 현황과 실제 사건 건수, CSV를 제공합니다. 상태는 1분 간격으로 90일 보관하고 기록 누락 구간을 선으로 잇지 않습니다. AI 추가 호출은 없습니다.
- **속마음:** 공개 발언에서 제거한 속마음 초안은 발언이 실제 전송됐을 때 관리자 자료에 기록합니다. 개인 RP·DM에는 월드 속마음을 제공하지 않고 기본 CSV와 운영 진단에도 넣지 않습니다.
- **AI 운영 진단:** 관리자 `/운영진단`은 공개 월드 상태·공개 전송 대화·생활 이력을 검토하고 PC의 `diagnostics` 폴더에 보고서를 저장합니다. 정기 진단을 켜면 1시간 간격으로 호출합니다. API 비용이 발생합니다. 별도 진단 모델·키를 설정할 수 있으며 자동 수정·재시작·Discord 보고서 공개는 없습니다.
- **API · Discord:** 기본 API 키, OpenAI 호환 API 주소, responses/chat 방식, 생성 모델, 제한 시간, 동시 생성 수 1~8을 설정합니다. 빈 응답과 미완료 응답은 전송하지 않습니다. 대기 중 사용자 답변은 자율 생성보다 우선하며 이미 실행 중인 생성은 중단하지 않습니다.
- **종료:** 과거 실패 기록은 진행 중 작업 수에 넣지 않습니다. 관리창을 닫을 때 봇 종료를 선택하면 모니터를 유지해 작업 종류·건수·경과 시간을 표시합니다. 진행 AI 호출에는 최대 30초의 종료 대기를 적용하며, 이후 연결 정리 중에는 SDK의 요청 제한 시간이 영향을 줄 수 있습니다.

## 적용 범위와 검증

현재 구현은 범용 생활 자료와 기존 RPBot 실행 구조의 연결입니다. Gateway와 Worker를 별도 운영체제 프로세스로 분리한 DDL 전용 실행 구조를 그대로 이식한 것은 아닙니다. 모든 자연어 표현을 이해하는 것을 보장하지 않으며, 불명확한 행동은 반영하지 않고 명시적인 명령을 제공합니다. 별도 관계 동선 학습·자동 상자 배송·고급 여가 대화 모집·모든 비멘션 심부름 표현은 추가 확장 대상으로 남습니다.

실제 Discord 장기 운영, Windows 실행 파일 빌드·배포와 API 제공업체별 실호출은 별도 확인이 필요합니다. 코드의 데이터·의존성·회귀 검사와 GUI 구성 검사를 실행해 확인합니다.
